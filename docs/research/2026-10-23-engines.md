# diagram-axi engines: D2 and Mermaid (research, 2026-10-23)

Lab: `scratchpad\research\engines-lab\` (d2cache\, d2\, d2js\, mmd\, scripts\). Machine: Win11, Node 24.19, Chrome at
`C:\Program Files\Google\Chrome\Application\chrome.exe`. Timings were taken while two other agents were running, so
process-spawn numbers are noisy (D2 CLI: 0.2 s when idle, 1.0-1.7 s under load); in-process numbers are stable.

## TL;DR recommendations
1. D2: use `@d2lang/d2@0.1.34` (WASM, same Go code as D2 v0.9.0) in-process for check + geometry + SVG. It is
   byte-identical to the CLI SVG (verified). Do NOT use the old `@terrastruct/d2` (stuck at 0.1.33, Aug 2025).
2. D2 PNG: either the pinned native binary (v0.9.0 has a built-in rasteriser, no browser) or rasterise the SVG in our
   own Chrome. Default to our Chrome page (one code path with Mermaid, no 18 MB download); binary is optional extra.
3. Mermaid: bundle `mermaid@12.2.0` + `@mermaid-js/layout-elk@1.0.1` into one IIFE with esbuild and run it in our own
   playwright-core page. Do not depend on `@mermaid-js/mermaid-cli` (needs puppeteer 25 + its own Chrome logic, ~1.6-2.0 s
   per call, no geometry, no parse positions).
4. Geometry: extract to a neutral model (boxes + polylines + label boxes), then adapt to the checker's scene. A D2 ->
   `analyzeScene()` adapter already runs against `dist/quality/analyze.js` (prototype `scripts\d2-to-scene.mjs`).
5. Set determinism knobs explicitly (see sections). D2 is deterministic out of the box; Mermaid needs `handDrawnSeed`,
   `deterministicIds` and an embedded font to be stable across machines.

### Pin + download + verify + cache from Node (no account, no API token)
Prototype `scripts\fetch-d2.mjs` (tested: 5.6 s first run on this link, instant on cache hit):
```js
const base = `https://github.com/terrastruct/d2/releases/download/${V}`;       // redirects to d2lang; plain fetch follows
const sums = await (await fetch(`${base}/SHA256SUMS`)).text();                 // "<sha256>  d2-v0.9.0-windows-amd64.tar.gz"
const buf  = Buffer.from(await (await fetch(`${base}/${asset}`)).arrayBuffer());
if (sha256(buf) !== wantedSha) throw ...;  // PIN the expected sha in our source, SHA256SUMS is only a fallback
// extract with `tar -xzf` (bsdtar ships in Win10+; GNU tar on linux/mac) into <cache>/.tmp-<pid>, then rename -> <cache>/d2-v0.9.0
```
Pinned checksums (v0.9.0): windows-amd64 `5f63b643de8f5a6dfb922d172e1b5496e4caf47497c33c4427cf1127f28c340f`,
windows-arm64 `dd05cab4...83e1`, linux-amd64 `5669ddc4...87a9`, linux-arm64 `ac2c0286...f913`,

### Determinism (verified)
CLI: 3 runs -> identical md5 (also with `--sketch`). WASM: 36 compile+render pairs across 12 corpus files x 3 engines,
all identical on repeat; WASM SVG == CLI SVG byte-for-byte (modulo the trailing "\n"). WASM sketch != CLI sketch (differs
at char ~196, size 39 KB vs 51 KB; bundling of fonts differs) - pick one path per run and keep it. TALA uses seeds
`--tala-seeds 1,2,3` (default), fixed => deterministic. Output embeds `data-d2-version` (use `--omit-version` to keep golden files
stable across patch upgrades).

### Errors: format, exit codes, mapping to TOON
CLI `d2 in.d2 out.svg` exit 1; stderr lines, one per error, **all errors reported** (compile), each `err: <abs path>:LINE:COL: message`
(first has prefix `err: failed to compile <name>: <path>:L:C: msg`); 1-based, col = start of offending token. Windows paths
contain `C:` so parse from the right: `/:(\d+):(\d+): (.*)$/`. Examples (verbatim messages):
- `3:3: connection missing destination`; `2:4: maps must be terminated with }`; `1:4: double quoted strings must be terminated with "`
- `3:15: expected "fill" to be a valid named color ("orange"), a hex code ("#f0ff3a"), or a gradient (...)` (suggestion embedded)
- `2:17: unknown shape "bogus"`, `4:18: expected "opacity" to be a number between 0.0 and 1.0`, `5:9: invalid style keyword: "bogus"`,
  `near key "nowhere" must be ... one of: top-left, top-center, ...`
- bad layout in `d2-config`: `bad usage: D2_LAYOUT "bogus" is not bundled ... The available options are: dagre, elk, tala`
Gotchas: **`d2 validate` (0.9.0) is parse-only** - semantic errors (unknown shape, bad colour, bad near) pass "Success!". So
`check` must run a full compile. `d2 fmt` on a bad file: `err: failed to fmt: <path>:2:4: ...`, exit 1. Missing file: exit 1.
Layout failures are rare; compile errors arrive before layout, so failing cases are cheap.
Best source for TOON: d2.js. `compile()` rejects with `Error.message` = JSON
`[{"range":"index,2:1:13-2:5:17","errmsg":"index:3:2: connection missing destination"}]`; range = `file,startLine0:startCol0:byte-endLine0:endCol0:byte`
(0-based; add 1 for line:col). Gives start AND end -> we can print `line:col` plus a caret span. All errors in one array.
TOON row: `errors[N]{line,col,endCol,code,message,suggestion}` where `suggestion` comes from a small regex table over `errmsg`
(maps must be terminated -> "add a closing }"; unknown shape -> list valid shapes; invalid colour -> hex form).
Exit codes for our CLI: 0 ok, 1 diagram errors (not tool failure) per AXI convention, 2 usage.

### Geometry out of D2 (no Go helper needed)
Option A (recommended): d2.js `compile()` returns `{diagram, graph}`. `diagram` is Go `d2target.Diagram` as JSON, i.e. the
`d2lib.Compile` + layout result - exactly what a Go helper would dump via `diagram.Shapes/Connections`, without installing Go.
- `diagram.shapes[]`: `id` (dot path, e.g. `g.x`), `type` (rectangle, hexagon, cylinder, oval, sql_table, class,
  text, ...), `pos{x,y}` (top-left), `width`, `height`, `level` (nesting), `label`, `labelWidth/Height`, `columns[]` (sql_table),
  `fields[]/methods[]` (class), fill/stroke/etc. Containers are shapes whose id is a prefix of other ids.
- `diagram.connections[]`: `id` like `(a -> b)[0]`, `src`, `dst` (shape ids), `label`, `labelWidth/Height`, `labelPosition`,
  `srcArrow/dstArrow`, `route[]` points, `isCurve`. dagre: `isCurve:true`, route = P0 then groups of 3 cubic-bezier control
  points (sample with ~12 steps/segment). elk/tala: orthogonal/polyline points (`isCurve:false`; SVG uses `L`/`S` corners).
- `diagram.root`, `legend`, layers/scenarios/steps (multi-board) - treat as separate scenes.
Option B (fallback, CLI only): parse the SVG. Each element is `<g class="base64(id)">` (e.g. `Zy54` = `g.x`,
`KGEgLSZndDsgYilbMF0=` = `(a -> b)[0]`); shapes inside `<g class="shape">` as `rect x y width height` / `path d` (hexagon,
cylinder); edges `path.connection d=...` (+ `marker-end`); labels `text x y` (text-anchor middle) and a `<mask>` of black
`rect`s = label gaps. Works but loses shape types and route semantics; use only if the WASM dep is rejected.
Sequence diagrams (verified): actors are `rectangle` shapes with pos/size, each message is a connection with route
`[[62,198],[212,198]]`, self-message a 4-point route, lifelines are extra connections with empty label and id
`(alice -- )[0]` (filter them), groups are rectangles. sql_table/class report whole-table boxes (rows are in `columns`/`fields`;
row boxes not given).

### Feature support (verified by compile+render, all 3 layouts)
sequence_diagram, sql_table (PK/FK constraints, column->column connections), class shape (+/- visibility, methods), containers,
`near` (constants like bottom-right / top-center), grid (`grid-rows/columns`), `direction`, themes, sketch, markdown labels,
icons (remote URLs fetched at render time - treat as network access; block or warn), `d2-config` vars. d2.js timings (warm,
Node, compile+layout): dagre 25-60 ms, elk 25-110 ms (first one ~200 ms), tala 95-1600 ms (3-30x slower); render 55-140 ms; cold
WASM start 1.3 s (first compile). Layouts: dagre/elk are deterministic and fast; tala best on architecture diagrams (needs
more time); sequence diagrams ignore the layout engine (all three produced identical 11,380-byte SVGs).

### ELK and look: handDrawn (verified)
- ELK: `mermaid.initialize({layout:'elk'})` or per-diagram frontmatter `---\nconfig:\n  layout: elk\n---` (works, 45-57 ms, larger SVG
  ~38 KB vs 18 KB due to neo look + elk edges). Applies to flowchart/state/class/er (unified renderer), not sequence/gantt/etc.
- `look: handDrawn` via initialize or frontmatter: works (flowchart 238 KB SVG, rough.js fills; class 74 KB). Seed it:
  `handDrawnSeed: 1`, else rough.js randomises and class/er SVGs differ every run.
- Portable SVG: labels are `foreignObject` HTML by default; set `flowchart:{htmlLabels:false}` / top-level `htmlLabels:false` if the SVG
  must render outside browsers (renders fine; check each diagram type).

### Validation: `mermaid.parse()` (verified)
`await mermaid.parse(src)` resolves `{diagramType, config}` or throws. Error shapes:
- Jison diagrams (flowchart, sequence, state, er, class, mindmap...): `Error` with `message` "Parse error on line N:\n...context\n---^\nExpecting 'A', 'B', got 'X'" and
  `e.hash = {text, token, line (0-based), loc{first_line (1-based), last_line, first_column, last_column}, expected[]}`.
  Use `hash.loc.first_line/first_column` (1-based line, 0-based col) -> line:col; `expected[]` -> suggestion ("expected one of ...").
  Caveat: an error at end of input is reported on a line past the last line (3-line doc -> "line 5"), and a dangling `A -->` is reported on
  the NEXT line; clamp to doc length. Test with frontmatter: strip frontmatter and add its line count back to be safe (not verified).
- Langium diagrams (pie, gitGraph, info, packet, architecture, radar, treemap...): plain `Error`, no `hash`;
  message "Parsing failed: ... Parse error on line 3, column 14: Expecting token of type 'STRING' but found `...`" ->
  regex `/line (\d+), column (\d+)/`. Both counted 1-based.
- Unknown type: `UnknownDiagramError` "No diagram type detected matching given configuration for text: ..." (no position; suggest the
  list of types and "first line must be e.g. flowchart LR"). Also for a typo like `flowchat`.
- Some bad inputs give raw TypeError (`timeline` with empty entry: "Cannot read properties of undefined (reading 'events')") - map to
  "diagram syntax error (unlocated)" and show the offending diagram type.
- Lenient: `classDiagram` with `+foo(` (unclosed) parses and renders. `parse()` does NOT catch render-time failures (e.g. gitGraph
  `checkout nowhere` fails at parse for the syntax but semantic errors appear in `render`): `check` = `parse()` then a real `render()` in try/catch.
Mermaid's `render()` on error injects an error SVG unless `suppressErrorRendering:true`; always call `parse()` first.

### Geometry (verified with getBoundingClientRect + SVG viewBox mapping)
Must run in a real DOM (insert SVG into the page; getBBox/getBoundingClientRect need layout). Generic extractor
`scripts`-style (code in `mmd\geom.mjs`): after `mermaid.render(id, src)` put `svg` in `#host`, then convert each element's
client rect to user space: `x = vb.x + (b.left - r.left) * vb.width / r.width`.
- flowchart/state/class/er (unified renderer): nodes `g.node` (id `<renderId>-flowchart-A-0`, `-classId-Animal-0`, `-entity-CUSTOMER-0`,
  `-state-Idle-2`), subgraphs `g.cluster`, edges `path[data-edge="true"]` with `data-id` and **`data-points` = base64 JSON array of the
  routed points** (exact polyline; the `d` attribute may be rounded with `Q` corners), edge labels `g.edgeLabel`. Verified: flow 6 nodes/5 edges,
  class 2/1, er 3/2, state 4/4. Use `path.getPointAtLength` sampling in the page when data-points is missing (marker/offset caveat: data-points are in
  the layout space of the root `<g>` - map them through `path.getCTM()`).
- sequence: `rect.actor` (note: actors appear twice, top and bottom; dedupe by `name`), `line.messageLine0/1` (dashed = messageLine1),
  `text.messageText`, `rect.note`, `g.loop`/`rect.loopLine`.
- gitGraph/mindmap/timeline: no node/edge ids worth keying on; use bboxes of `.commit-*`, `.mindmap-node`, `.timeline-*`; edges are
  `path.edge`/`path.branch`. For these types report aggregate-only inspect (counts, bbox, overlaps) rather than edge-level checks.
- Fonts: Mermaid measures text with the page's fonts (default `trebuchet ms, verdana, arial`). Geometry therefore **differs across machines
  unless a font is embedded**; set `themeVariables.fontFamily` to a font we ship in the page (excalidraw-axi already has embedded-fonts).

### Determinism (verified)
Fresh page, same render id, same corpus, 2 runs: flowchart, mindmap, sequence, state, timeline identical; **class and er differ** (rough.js
random in shape paths) until `handDrawnSeed: 1` is set -> then identical. With `deterministicIds:true, deterministicIDSeed:'x',
handDrawnSeed:1`: 7 of 8 types identical. **gitGraph still varies** (viewBox height 171.6 vs 174.4; auto-generated commit ids are random and
change label widths) - give commits explicit `id:` or canonicalise before measuring. Re-rendering twice in the same page differs only by a
global counter (`actor1` vs `actor3`), so render each diagram with a unique/fixed id and don't compare same-page re-renders byte-wise.

## Shared geometry extraction for the QA checker

Checker scene model (src/quality/analyze.ts): Excalidraw elements. Node = `rectangle|ellipse|diamond` {x,y,width,height}; label = `text` with
`containerId` (node/edge) or id `zone-title-*`; zone = `rectangle` with id prefix `zone-`; edge = `arrow` {x,y,points[[dx,dy]...],
startBinding/endBinding{elementId}}. Adapter pipeline: `engine output -> neutral {nodes[{id,kind,box,shape,parent}], edges[{id,src,dst,poly[],label?}],
labels[{box,ownerId}]}` -> `toScene()`.
- D2: from `diagram.shapes/connections` (exact, no SVG parsing). Prototype `scripts\d2-to-scene.mjs`: translates origin to >= 0 (the checker
  flags x<0), samples dagre beziers, maps shapes with children to `zone-N` + `zone-title-N`, others to rectangle/ellipse/diamond by `type`.
  Ran `analyzeScene` on d2-bakeoff sources (3 corpus diagrams x dagre/elk/tala): works, 1-60 ms per scene; e.g. k8s: 9 nodes, 2 zones, 9 edges,
  3 crossings. Findings still contain adapter artefacts (label-stored-offset from my midpoint labels, text-overflow from bad label sizes):
  use D2's `labelPosition`/`labelPercentage` for edge labels (route point at that fraction of length) and exclude `label-stored-offset`/
  `text-exceeds-inscribed` (Excalidraw-specific) for engine-native diagrams.
- Mermaid: in-page extractor above -> neutral model. Edge ends: bind by `data-id` pattern `L_<src>_<dst>_<n>` (flowchart) /
  `id_<src>_<dst>_<n>` (class, er) / list order (state `edge0..`). Node boxes from the shape element, not the `g` (the g includes labels/
  decorators).
- Shared SVG fallback (any engine, or user-supplied .svg): in Chrome, `querySelectorAll('rect,path,ellipse,polygon,circle,text')`,
  `getBBox()` + `getCTM()` to user space, `getPointAtLength(t*len)` for polylines; classify by engine conventions (D2 `g.shape` / `path.connection`;
  Mermaid `g.node` / `path[data-edge]`). Everything runs in the page we already launch.
Rules that transfer well: node-overlap, arrow-through-node, label-on-node, label-label-overlap, group-containment/zone-intrusion, crossings,
aspect-ratio, route-ratio, text-overflow. Limits:
1. Bezier/curved routes need sampling; rounded corners (`Q`, `S`) and markers shift endpoints by a few px -> use larger tolerances (3-4 px) than Excalidraw native.
2. Non-rectangular shapes (hexagon, cylinder, rhombus): need `shapePoly` equivalents; use bbox + inset for unknown shapes.
3. Engine owns layout: findings are advisory (we cannot nudge nodes), so output should say "engine/direction/layout alternatives" instead of coordinates
   (e.g. try `--layout elk|tala`, `direction`, or reduce width).
4. Mermaid foreignObject labels and font-dependent measurements -> machine dependent unless fonts are embedded; Mermaid edge labels are separate
   boxes (`g.edgeLabel`) but their placement is part of the engine's layout (rarely overlapping).
5. Sequence, sql_table, class, timeline, gitGraph, mindmap: boxes/lines are structured, not graph-routed; run only overlap/overflow/bounds checks, skip crossing/route-ratio
   (sequence arrows cross lifelines by design - filter D2 lifeline connections `(x -- )`).
6. d2 grid/near/legend and multi-board (layers/scenarios/steps): check each board separately; `near` elements have no connections.
7. Rotated/skewed text (gitGraph labels) -> use `getBoundingClientRect`, not `getBBox`.

## Suggested AXI surface
- `check`: D2 via d2.js compile (all errors, line:col + endCol + suggestion), Mermaid via `parse()` then a try-render; TOON `errors[N]{line,col,message,suggestion}`;
  exit 0 even if the file has errors? (follow axi-axi convention already in repo).
- `draw/render`: `--engine d2|mermaid`, `--layout dagre|elk|tala` (D2) / `elk` (Mermaid flowchart family), `--look sketch|hand`, `--theme`, `--pad`, `--scale`,
