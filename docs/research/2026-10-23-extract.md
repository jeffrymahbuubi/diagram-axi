# diagram-axi `extract`: code-structure to graph, design research

Date: 2026-10-23. Scope: survey of extractors, one-hour experiments on this repo (57 TS files), recommendation.
Conventions: "measured" = I ran it here; "claimed" = from docs/vendor pages; "unverified" = from memory, check before relying.

## 1. Summary of the recommendation

1. Own the aggregation and the normalized graph; treat every external tool as a replaceable adapter.
2. v1 = static **import/module graphs** for TS/JS and Python, built in-process (no external binary needed):
   - TS/JS: `oxc-parser` + `oxc-resolver` (measured: 57 files, 201 import edges, 0 unresolved, 24 ms, 6.4 MB node_modules).
   - Python: tree-sitter-python (web-tree-sitter wasm) with a small resolver; optional `--via grimp` adapter when Python is present.
   - dependency-cruiser stays an optional adapter (`--via depcruise`), not the default.
3. v1.5 = call graphs, opt-in and labelled `confidence: heuristic|exact`. TS via pinned TypeScript 6.x (or 7.1 API once stable); Python via pyan3 adapter or tree-sitter name matching.
4. v2 = Go/Rust/Java adapters (they ship strong native tooling), SCIP/LSP for language-agnostic precise call/reference edges, OTLP traces to sequence diagrams, Prisma/SQL to ERD.
5. Readability is the product: a budgeted "cut" over the containment tree (<= 25 nodes), edge weights, hub suppression, `--focus/--depth`, explicit drill-down hints.

## 3. Per-area notes

### 3.1 JS/TS import graph (measured on `excalidraw-axi/src`, 57 files, ESM + NodeNext, `.js` specifiers for `.ts` files)
- dependency-cruiser 18.7.0, defaults: `src` as a directory argument returned **0 modules** on this Windows setup; `src/index.ts` returned 8 modules with every local import `couldNotResolve` because specifiers are `./x.js` but files are `.ts`; `"src/**/*.ts"` worked for discovery. `--include-only "^src"` then silently dropped all unresolved edges, yielding 0 edges (a misleading "clean" result).
- Working config: `{"options":{"tsConfig":{"fileName":"tsconfig.json"},"tsPreCompilationDeps":true,"enhancedResolveOptions":{"extensions":[".ts",".js",".json"],"exportsFields":["exports"],"conditionNames":["import","require","node","default"]},"doNotFollow":{"path":"node_modules"},"includeOnly":"^src"}}`. `extensionAlias` is rejected by its schema. Result: 57 modules, 183 edges, 110 KB JSON, 6.8-9.4 s wall (mostly `npx` + TypeScript load). Raw JSON is far too large for an agent; aggregating by `src/<dir>` gives 12 nodes and 23 edges; top weights: commands->output 19, commands->scene 9, layout->dsl 7; 3 modules in cycles; most imported `dsl/ast.ts` (20 dependents).
- Its own `--collapse 2 --output-type mermaid` produced nodes with blank labels (`[" "]`) on this input, so do not rely on its built-in summarisation; take the JSON (or its API) and collapse ourselves.
- oxc approach (script in `research/extract-lab/oxc/t.mjs`): `parseSync` returns `module.staticImports` with byte offsets (line numbers by counting newlines), `oxc-resolver` handles tsconfig `paths`, `extensionAlias: {".js":[".ts",".js"]}`; 24 ms for 57 files, 181 internal + 20 external edges, 0 unresolved. Also read `staticExports` (re-exports), `dynamicImports`, and `isType` to flag type-only edges.
- madge: simple but no release since 2024-08; skott fine but adds nothing we need once we own aggregation.

### 3.2 TypeScript call graphs
- TS 7.0 (2026-07-08, Go-native, ~10x faster) shipped **no** programmatic API; ts-morph 28 requires TS 6. TS 7.1 beta (2026-10-20) ships `typescript/sync` and `typescript/async` entry points; RC ~mid Nov, stable planned 2026-11-24. Reported ts-morph-over-RPC slowdown (158 s vs 199 s in ts-morph issue 1685) shows chatty per-node calls are costly across the process boundary.
- Plan: v1.5 pins `typescript@6` as an optional lazy-installed dependency for `--precise`; write the extractor against a tiny interface (`resolveCallee(node) -> symbol`) so a 7.1 backend can replace it. Without it, fall back to syntactic call extraction (tree-sitter/ast-grep: callee identifier matched against imports of the file), tagged `confidence: heuristic`.
- Accuracy limits: dynamic dispatch, callbacks passed by value, DI containers, decorators/metadata, `any`-typed receivers.

### 3.3 Python
- Imports: grimp is the best engine (queryable graph, chains, line numbers via import details, BSD-2). Cost: requires a Python env where the target package is importable. Hence default to a tree-sitter importer (handles absolute, relative, `from . import x`, `__init__.py`, src layout) and offer `--via grimp`. Mark imports under `if TYPE_CHECKING:` (import-linter can exclude these) and function-local imports as `kind: import, lazy: true`.
- Calls: pyan3 2.9.0 (revived Feb 2026, Python 3.10-3.14 syntax, module-level mode with cycle detection) is the best open option; run as a subprocess (license is GPL-family: verify; do not bundle). code2flow is the lighter alternative (MIT) but looks low-activity.
- Classes: pyreverse emits mermaid/puml/dot class + package diagrams; useful as a v2 `extract classes` source.

### 3.4 Go / Rust / Java (use the native tool, parse its output)
- Go: imports via `go list -json -deps ./...` (no extra install); calls via `golang.org/x/tools/cmd/callgraph` (static/cha/rta/vta) or go-callvis (`-focus`, `-group pkg|type`, `-algo`); goda for set-algebra queries (`reach(a, b)`). go-callvis is MIT but last released 2025-01.
- Rust: `cargo modules dependencies --focus-on <path> --layout none|dot ...` and `structure` (tree). Output dot -> parse. Requires a compilable crate.
- Java: `jdeps -verbose:package|class -dotoutput dir app.jar` or `-summary`; bytecode input, so source-link metadata (file:line) must come from a separate class->source map. Fine for "which packages depend on which"; poor for call paths.

### 3.5 Tree-sitter tools
- tree-sitter tags (`tags.scm`) gives definition/reference name pairs per file in every language that ships queries: the cheapest cross-language heuristic call/ref graph (match callee name to a definition via imports then global name). tree-sitter-graph lets one declare real graph construction rules but requires writing them per grammar. stack-graphs (precise name resolution) was archived by GitHub; RUSTSEC-2026-0303 (2026-09-22) flags it unmaintained. Do not depend on it.
- web-tree-sitter 0.27.1 (MIT, 4.7 MB) + prebuilt wasm grammars is the portable route (no native compile). ast-grep napi is an alternative with patterns (good for framework idioms in 3.6).

### 3.6 LSP call hierarchy as language-agnostic option
- Methods: `textDocument/prepareCallHierarchy`, `callHierarchy/incomingCalls`, `callHierarchy/outgoingCalls` (LSP 3.16+).
- Support: gopls (also CLI `gopls call_hierarchy file.go:L:C`), typescript-language-server (gated on TS >= 3.8), rust-analyzer; pyright/Pylance support it (unverified here); Astral `ty` did not as of the Dec 2025 issue (#1976), status in 2026 unknown; jdtls supports it (unverified).
- Costs: need a server installed per language, start-up/indexing time, one request per symbol, so whole-repo extraction is slow. Right use: **drill-down for one focus function** (`extract calls --focus file.ts:fn --depth 3 --via lsp`), results tagged `confidence: exact` and cached.

### 3.7 SCIP (worth knowing)
- Language-agnostic protobuf index (`index.scip`), `scip print --json`; indexers: scip-typescript 0.5.2 (Apache-2.0), scip-python, scip-java, scip-dotnet, rust-analyzer. Each definition occurrence can carry an enclosing range, so "reference to symbol S located inside function F" yields call/use edges for any language (my design inference; verify with a spike). Caveats: references include type uses (filter by symbol kind), indexers need dependencies installed, indexing is minutes on large repos. Candidate backend for `--precise` across languages in v2.

### 3.8 OpenTelemetry traces to sequence diagrams (runtime request paths)
- Input without any network: OTLP JSON Lines per the OTel File Exporter spec (`resourceSpans[].scopeSpans[].spans[]` with `traceId`, `spanId`, `parentSpanId`, `name`, `kind`, `startTimeUnixNano`, `endTimeUnixNano`, resource attr `service.name`); Python SDK has an OTLP JSON file exporter. Also accept Jaeger JSON export.
- Mapping: participants = distinct `service.name` (plus db/queue peers from `db.system`, `messaging.system`, `peer.service`); a message is emitted where a child span's service differs from its parent's (CLIENT->SERVER pairs; PRODUCER->CONSUMER as async arrow); intra-service spans are folded into the participant (or into a note when `--detail spans`). Sort by `startTimeUnixNano`. Collapse repeated sibling calls into `x N` and label with p50 duration.
- Budget: <= 8 participants, <= 25 messages; beyond that, pick the critical path (longest duration chain) or the slowest/failed (`status.code=ERROR`) subtree, and print "N more calls omitted".
- Existing tools (tracemaid: Python, Mermaid, ML span selection; otel2puml: PlantUML activity) show demand but are heavier than a ~150-line parser; do not adopt, borrow the span-selection idea only.

### 3.9 Schema to ERD
- Sources, in order of fidelity per effort: (1) `schema.prisma` via prisma-ast (pure JS, models/fields/`@relation(fields, references)`); `getDMMF` if resolved implicit M:N relations matter; (2) `pg_dump --schema-only` or `schema.sql`/`structure.sql`: parse `CREATE TABLE`, `ALTER TABLE ... ADD CONSTRAINT ... FOREIGN KEY` (sqlglot in Python, or `libpg-query` wasm in Node); (3) migrations folder: replay in lexical order into an in-memory model (best effort, flag unparseable files); (4) live DB via `tbls` (`out -t mermaid|dot`, `--distance N`, `schema.json`), user-supplied only, never default.
- Output: D2 `sql_table` shapes with `constraint: primary_key|foreign_key|unique` rows and FK edges `orders.user_id -> users.id` (D2 draws connections to exact rows under ELK/TALA); Mermaid `erDiagram` as an alternate.
- Budget: >25 tables -> `--focus users --distance 2` (tbls-style), or group by schema/prefix; default compact mode shows only PK + FK columns; `--columns all` to expand.

### 3.10 archify "repository-backed authoring" (read `archify/references/repository-authoring.md`, 126 lines)
- It has **no extractor**; it is a protocol for an LLM to read a small connected slice (entry points, manifests, imports, call sites) and then author JSON with evidence. Stop rule: "no node/edge/citation count to hit".
- Ideas worth copying:
  1. Freeze identity: `git rev-parse HEAD`, origin URL with credentials stripped, `git status --short`; pin URL + 40-char rev in `meta.repository`; evidence is verified against committed bytes, dirty paths reported to the user, not recorded in the artifact.
  2. `link_mode`: web links only for supported GitHub/Gitee/GitLab HTTPS origins; SSH or unknown forge becomes `local-only` (keep URL + revision, no clickable link).
  3. Evidence shape: `sources: [{path, line, end_line}]`, at most 3 ranges, only on primary elements (components, participants, ERD entities, states...). Relationships carry none: cite the call/write site on the owning element.
  4. Truthfulness rules: distinguish configured provider vs injected adapter vs local stub vs durable service; exported-but-uncalled is "optional capability", not a runtime edge; write unresolved questions beside the claim ("durability unknown").
- Implication: `extract` supplies the mechanical 80% (what imports what, with spans) and archify-style rules stay as agent guidance for the semantic 20% (roles, runtime ownership, side effects). Put those rules in the `extract` skill text.

## 4. Abstraction

```
Extractor (adapter)  ->  RawGraph  ->  Normalize  ->  Aggregate(view params)  ->  Emit(.exd | d2 | mermaid)
 oxc-ts, ts-lsp, py-ts, grimp,           ids, kinds,     cut / focus / filter       + sidecar map (ids -> spans)
 depcruise, go-list, cargo-modules,      weights, spans  hubs / externals
 jdeps, otlp, prisma, sql, scip
```

Normalized graph (JSON, the stable internal contract; also `extract ... --format json` for tools):

```jsonc
{ "schema": 1,
  "meta": { "repo": {"url": "https://github.com/o/r", "rev": "<40-hex>", "dirty": ["src/a.ts"], "linkMode": "web|local-only"},
            "extractor": {"name": "oxc-ts", "version": "0.155.0", "confidence": "exact|heuristic"},
            "root": "src", "langs": ["ts"], "stats": {"files": 57, "edges": 201, "unresolved": 0} },
  "nodes": [ { "id": "src/layout/engine.ts", "kind": "file",      // file|dir|package|module|class|function|type|service|endpoint|table|column|external
               "label": "engine.ts", "parent": "src/layout", "lang": "ts",
               "path": "src/layout/engine.ts", "span": {"line": 1, "endLine": 412},
               "attrs": {"loc": 412, "exported": 9, "test": false} } ],
  "edges": [ { "from": "src/commands/draw.ts", "to": "src/dsl/ast.ts",
               "kind": "import",                 // import|call|http|db|extends|implements|fk|event|publish
               "weight": 1, "typeOnly": false, "dynamic": false, "lazy": false,
               "confidence": "exact",            // exact|heuristic|inferred
               "evidence": [ {"path": "src/commands/draw.ts", "line": 4} ] } ] }
```

Rules: ids are repo-relative paths (files/dirs) or `path#symbol` (functions: `src/a.ts#parse`), stable across runs so drill-down commands and diffs work; externals are `ext:<package>`; the containment tree comes from `parent`, edges are always between leaves and rolled up later; every adapter must fill `evidence.line` or set `confidence` lower.

## 5. Aggregation and collapse (keep <= 25 visible nodes)

1. Filters first: hide externals (default; one aggregate node `external (12)` if `--externals`), tests (`*.test.*`, `test/`), generated/vendor paths, type-only edges (`--types` to show), barrel re-exports collapsed ("see through" index files: edge A->index->B becomes A->B).
2. Containment cut: start with the root's children visible; repeatedly expand the visible directory with the highest score `= subtreeSize * (1 + weightedDegree)` while the visible count stays <= budget (`--max-nodes 25`). A collapsed directory node shows `layout (17 files)`. Single-child chains (`src/main/java/com/x`) are compressed into one label.
3. Edge roll-up: sum weights between visible nodes; label `x7` above weight 1; drop self edges; keep cycles (highlight edges that sit on a strongly connected component, count them in the summary).
4. Hub suppression: nodes with dependents above the 90th percentile (measured: `dsl/ast.ts` has 20 of 57) are drawn once, outlined, with edges dropped and the note `used by 20`; `--hubs show` restores edges. This is what makes layered layouts legible.
5. Focus mode: `--focus <id> --depth N [--dir in|out|both]` does BFS from the entry, then applies steps 2-3 to the reached subgraph; unreached neighbours collapse into `... +k more` stubs carrying the expand command in the hint.
6. Centrality when no entry is known: rank by PageRank (also betweenness for bridges); expand highest first; show top-k "core" modules plus the dir skeleton.
7. Summary lines in the CLI output (compact, TOON-style like the rest of the tool): `nodes 17 (of 57 files) edges 23 hidden externals 12 hubs 2 cycles 1`, then next-step hints (`expand: extract imports src --expand src/layout`).

## 6. Choosing diagram kind and engine from data

| Extracted data | Diagram | Default engine | Why / rule |
|---|---|---|---|
| module/dir import graph, nested | layered flow with nested groups | d2 (ELK) when > 12 nodes or nesting depth >= 2; excalidraw when <= 12 nodes and hand-editing is expected | D2 containers and ELK handle size; excalidraw for whiteboard use |
| import graph for GitHub README/PR | flowchart | mermaid | renders natively on forges; subgraph per dir |
| call path / request path (<= 8 participants, ordered) | sequence | mermaid (portable) or d2 `sequence_diagram` | ordering is the content |
| call graph (unordered, > 8 nodes) | flow grouped by file/class | d2 | not a sequence; group by module |
| service-to-service static edges (http/db/event) | architecture, nested by deployable | d2 / excalidraw | kind icons; db nodes as cylinders |
| schema | ERD | d2 `sql_table` (mermaid `erDiagram` alternate) | row-level FK edges |
| class hierarchy | class diagram | mermaid `classDiagram` or d2 `class` | extends/implements edges |
Decision function: `kind = f(edge kinds present, ordered?, node count)`, engine = table default, always overridable with `--engine`. Print the choice and the reason in the summary so the agent can override.

## 7. Source links for drill-down

- Every node and edge keeps `{path, line, endLine}`; the `.exd` stays lean, so write a **sidecar** `x.exd.map.json` (`id -> {path, span, deps, evidenceLines}`) next to the output, plus `meta.repository {url, rev, linkMode}` pinned as archify does.
- Engine-native links where supported: D2 `link:`, Mermaid `click id href`, Excalidraw element `link`; URL = `https://<forge>/<o>/<r>/blob/<rev>/<path>#L<line>-L<endLine>` when `linkMode: web`, else `file:///` or `vscode://file/<abs>:<line>`.
- Commands read the sidecar so an agent can go from a box to code without opening the SVG: `diagram-axi extract open <diagram> <id>` prints `path:line-endLine` and the first N lines (with `nl -ba`-style numbering, as archify recommends).
- Drift guard: sidecar stores `rev` and per-file content hashes; `extract check x.exd` reports `stale: 3 files changed since rev` so a diagram is never presented as current when it is not.

Defaults agents get without flags: `extract imports .` auto-detects languages, hides externals/tests, budget 25, writes `./imports.exd` plus sidecar, prints the summary and 2-3 drill-down hints. Exit non-zero only on extraction failure, not on large graphs (the cut handles size). Errors name the fix (e.g. "tsconfig not found; pass --tsconfig").

## 9. Phased plan

- v1 (small, high value): `extract imports` (TS/JS via oxc; Python via tree-sitter), aggregation engine, sidecar + `extract open/check`, d2/mermaid/excalidraw emit through the existing `.exd` pipeline, tests with golden graphs (use this repo: expect 57 files / 181 internal edges / 12 dir nodes / 23 dir edges).
- v1.5: `extract calls` (TS precise via pinned TS 6, heuristic otherwise; pyan3 adapter), `extract schema` for Prisma + `pg_dump` DDL, `extract trace` (OTLP JSON).
- v2: Go/Rust/Java adapters, SCIP/LSP `--precise`, static HTTP/db edges via ast-grep patterns (fetch/axios URL literals matched to Express/FastAPI/Nest route registrations; ORM calls to tables), migration replay.

## 10. Risks and open questions

- Path handling on Windows: dependency-cruiser's directory argument and bash path mangling both bit me; normalize to forward slashes at the adapter boundary and test on Windows CI.
- Resolution fidelity is the main correctness risk: tsconfig `paths`, project references, monorepo workspace links (treat workspace packages as internal), `exports` maps, Python namespace packages. Report `unresolved: N` prominently; never silently drop (the include-only 0-edge result above is the anti-pattern).
- Heuristic call edges can mislead: always render dashed + legend, and carry `confidence` through to the emit stage.
